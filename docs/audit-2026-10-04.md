## Independent review findings

A second reviewer reproduced five additional defects in the prior audit
candidate `f1d36010b38b3c5b5bab4fdafb4aa9740fb1f427` using persistent storage,
fresh processes and coordinated concurrent operations. The fixes add regression
coverage for the observed failure conditions.

| Defect | Correction |
| --- | --- |
| Startup could create an empty primary collection and then expire the only recoverable old collection | A persisted marker authorizes cleanup only after replacement metadata commits, and only while the exact replacement collection UUID is still primary. Legacy, unmarked and ambiguous backups remain available. |
| Staged writes lost the original basename for Dockerfile, Makefile and Tiltfile | Parser selection receives a validated logical basename while all file I/O continues to use the staged file. |
| Live mutations accumulated historical BM25 payloads before lexical initialization | Live changes invalidate the lexical state without appending document payloads; collection is restricted to the isolated rebuild path. |
| A query could cache temporary empty results during a failed delete and keep them after rollback | Mutation boundaries invalidate the cache in `finally`; generation checks also reject delayed writes from older queries. |
| FTS5 migration counted its source before acquiring the mutation lock | Count, stream and completion publication share the same source snapshot. |

Lifecycle validation includes five persistent-storage scenarios executed across
16 processes, extensionless add/update/rollback tests, and real barrier-driven
cache races. Retaining an ambiguous backup is not automatic recovery: operators
still need to inspect and restore the correct data. Handled rollback is not a
claim of crash-proof atomicity across independent files and stores.

### Additional rollback finding

The reviewer then reproduced a sixth defect: if mutation persistence failed and
vector rollback also raised, the document inventory could disagree with the
stored chunks. Filtered search could omit a restored source. After a process
restart, incremental indexing could skip a missing or wrong document version
because its source timestamp was unchanged. A two-document, 16-scenario
independent baseline retained one healthy source and exposed five persistent
failure cases after restart. Equal aggregate chunk counts did not prove correct
document identities or content.

The follow-up at `199f4c3` restores the committed inventory before attempting
backend rollback and records uncertain sources in a bounded, validated,
atomically replaced recovery file. Incremental indexing retries only those
sources, bypasses their checkpoints and cleans up failed-add orphans. Records
are removed only after metadata commits; FTS5 remains unavailable while repairs
are pending. The normal path adds no scan of the corpus's vectors or texts.
See [rollback recovery operations](reindex-operations.md#recovery-after-a-failed-document-rollback)
for failed-record persistence, malformed records and isolated rebuild recovery.

Nineteen new regression cases failed before the patch. The implementer's final
focused/regression selection passed 177 tests, including 44 tests of recovery,
cache concurrency, bounded records and derived lexical state. Recreating an
orchestrator in those unit tests is distinct from the independent reviewer's
fresh-process matrix; the final independent verdict and integrated checks are
required before release.

## Search behavior and evaluation design

Folder filters now apply before candidate selection in all retrieval backends.
They accept paths relative to the document root, recurse through descendants,
intersect with categories and give exclusions precedence. Validation rejects
absolute paths, parent traversal, alternate data streams and escaping links.
See [search scope and retrieval quality](search-quality.md) for the contract,
examples and the additional work performed by an uncached scoped query.

The previous semantic path capped its internal candidates at the configured
public result limit. The weighted fusion could then fill the reranker's entire budget
with lexical hits before it saw semantic-only candidates. The correction keeps
the internal pool separate from the output limit and reserves up to one result
page from each contributing channel within the same bounded reranking budget.
It does not increase the default model size, candidate multiplier or alpha.
Explicit alpha zero and one remain single-channel searches.

Diagnostic evaluation used 60 positive questions: the original 24, an older
12-question holdout and 24 paired Portuguese/English questions. A source hit
requires an expected source among the first ten results; an evidence hit also
requires the expected supporting passage. The paired set was evaluated before
the final algorithm choice, so these are development diagnostics, not unbiased
estimates of future-query quality. Known failures and regressions are retained.

| Diagnostic set | Source hits before → after | Evidence hits before → after | MRR@10 before → after |
| --- | ---: | ---: | ---: |
| Original 24 | 14 → 17 | 12 → 14 | 0.5417 → 0.5685 |
| Older holdout 12 | 6 → 7 | 6 → 6 | 0.4167 → 0.4333 |
| Paired 24 | 13 → 13 | 10 → 11 | 0.4514 → 0.5000 |
| Total 60 | 33 → 37 | 28 → 31 | — |

The paired set's first-result hits increased from 9 to 11. Sequential local
uncached median latencies changed from 109.1/132.9/133.6 ms to
116.6/131.7/137.0 ms for the three sets. These timings are not a controlled
latency guarantee and the changes do not improve every query.

A further reserve of 12 natural-language questions, paired across six new
sources, was frozen before the final algorithm was tested on it. Its source
selection excluded 491 paths seen in prior evaluation sources or returned
results. It is evaluated only after runtime freeze, on both the baseline and
candidate. Its answers are not used to retune this release.

## Multilingual model comparison

An isolated CUDA experiment re-embedded 70,083 existing chunks with
`intfloat/multilingual-e5-large`, 1024 dimensions, correct query/passage prefixes
and batch size eight. It took 1,186.58 seconds and sampled peak process RSS of
1,810,341,888 bytes. This excludes source parsing and uses a different batch
size from the BGE full-index run; it is not a like-for-like indexing benchmark.

With the same reranker, E5 produced 36 source hits and 31 evidence hits on the
60 diagnostics, compared with 37 and 31 for the corrected BGE default. These
results do not justify switching the default model. A larger multilingual
embedding model alone does not guarantee better ranking when the corpus,
candidate selection and English-trained reranker also affect the result.

ONNX Runtime rejected external weights reached through escaping model-cache
symlinks in the initial E5 attempt. A complete, materialized cache copy resolved
that error without disabling Runtime's path validation. Separate real CPU and
CUDA checks verified the documented `paths.models_cache_dir` procedure, finite
vectors, all three synthetic Portuguese-to-English source matches and minimum
CPU/CUDA cosine similarity of 0.999999858. No production model was migrated.
